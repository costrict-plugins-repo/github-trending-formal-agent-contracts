## 記録の読み方

どの記録でも、まず次の4点を確かめてください。

- **誰が実行したか**：人か、エージェントによる模擬か。模擬の場合は、何を読んでよい設定だったか、ユーザー役の答えが台本だったかどうか。
- **環境**：OS、Node.js の版、Java の有無、Claude Code の版（実際のセッションで実行した場合）。
- **どこまで進んだか**：どのプロンプトの後で、どのコマンドを実行し、何件のテストが成功・失敗したか。止まった場合は、どこで何が表示されたか。
- **ツールが確かめたことと、確かめていないこと**：テストランナーや VDMJ の出力がある項目と、LLM が書いただけの項目は分けて書いてあります。「テストが通った」は「仕様を機械検証した」と同じ意味ではありません。

記録の中のテスト件数・証明責務の件数・所要時間は、その日のその試行の値です。README や記事に転記する数値ではありません。

## 常に付く注意

エージェントによる模擬試行は、人による実行ではありません。エージェントはスキルの文面を読み慣れており、答えに迷わず、入力の待ち時間もありません。模擬試行の所要時間はエージェントの処理時間であり、人が同じ時間で終えられることを示しません。また、プラグインを読み込んだ実際の Claude Code セッションではないため、依頼文からスキルが正しく起動するかどうかは確かめていません。

## まだ無い記録

- 作者自身による、時間を計った通し実行
- クリーンなコンテナ（何も入っていない環境）での実行
- プラグインをインストールした実際の Claude Code セッションでの実行
- README の文面だけを見て進めた実行（これまでの試行は README を読んでいません）
- クイックスタート B を、Java と VDMJ の導入から通した実行（2026-11-11 の2回の試行は、どちらも導入済みのツールを使いました。導入手順の文書のとおりに、何も入っていないマシンへ入れた実行はありません）
- 複数のエージェントが通信する仕様（PROTOCOL.md / API-SIGNATURES.md を作る経路）での実行
- Python を対象言語にした実行
- 3つのプロンプトと verify-spec 以外のスキル（integrated-workflow など）での実行
- verify-spec の、ラウンド4が通っていない場合での実行（実装やテストがまだ無い状況、QuickCheck が反例を出す仕様、smt-verify の実行、など。一覧は 2026-11-11 の記録）
- 試行で使った v26.4.0 以外の Node.js での実行（README が下限とする 22.18 を含む）

これらが揃うまで、「初めての人が何分でテスト成功まで進めるか」について、このリポジトリに測定値はありません。

### 作者による計時つき実行の条件

[改善戦略](../../design/improvement-strategy-2026-10.md)の P3 は、成功の目安を「作者が、Java の無い検証環境で、README だけを見て、15分以内にテストの成功まで進む。その記録を時刻つきでこのディレクトリに置く」としています。この実行はまだ行っていません。行うときは、次の条件で記録します。

- **環境**：戦略文書が (a) と呼ぶ、Java の無いコンテナ（`node:22-bookworm-slim`）。検証環境をこのディレクトリに定義する作業は戦略の P2 の項目で、まだ行っていません。
- **見てよいもの**：README だけ。
- **計り方**：開始と終了をどこに置いたかを書きます（下の「記録の追加のしかた」の3）。
- **読み込まれたスキルの版**：計り始める前に、README の「インストールの確認」で、クイックスタート A が前提とする版のスキルが読み込まれていることを確かめ、結果を記録に書きます。同じ版番号のプラグインが既に入っている環境では、前の版のスキルが残っている可能性があります（入れ直しで置き換わるかどうかは未確認です）。

## 記録の追加のしかた

1. `YYYY-MM-DD-<短い名前>.md` を作り、上の一覧に1行足します。
2. 次の3点を必ず書きます。
   - **環境**：OS、Node.js の版、Claude Code の版、Java の有無。実際のセッションで実行した場合は、プラグインの入れ方（コミュニティ経路かリポジトリ経路か）と、define-contract・generate-code・generate-tests の版（各 `SKILL.md` の `metadata.version`）
   - **どのプロンプトの後で止まったか**：最後まで進んだ場合は、実行したコマンドと結果の件数
   - **何が表示されたか**：メッセージをそのまま写すか、期待と違った点
3. 実行者が人かエージェントかを書きます。時間を書く場合は、計り方（開始と終了をどこに置いたか）も書きます。
4. ツールの出力が残っていないことを「検証済み」「証明済み」と書きません。実行していない確認は「未実行」と書きます。
5. 生成されたファイルを添える場合は、記録と同じ日付で始まるディレクトリに置き、`node_modules/` は含めません。

リポジトリに記録を置くほどではない報告は、Issue で受け付けています（[CONTRIBUTING.md](../../CONTRIBUTING.md) の「初回実行の報告を歓迎します」）。
